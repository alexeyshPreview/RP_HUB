
# 🎮 RP_HUB

**RP_HUB** — специализированное пользовательское приложение и экосистема для игроков rp сообществ. платформа объединяет в себе социальные функции, аналитические инструменты и новостной агрегатор для комфортного взаимодействия с игровыми мирами.

### ⚡ Ключевой функционал платформы

* **👤 Персонализированный личный кабинет** — единый профиль пользователя для управления игровыми аккаунтами, личными настройками и безопасностью авторизации через единую систему учетных записей.
* **💬 Модуль real-time общения** — внутренний сервис мгновенных сообщений (чат), поддерживающий мгновенный обмен данными, создание диалогов и групповых чатов для координации игровых фракций и сообществ.
* **📰 Агрегатор актуальных новостей** — единая лента свежих событий, обновлений и анонсов популярных roleplay-проектов. вся важная информация собирается в одном месте без необходимости посещать десятки форумов.
* **📊 Аналитика и онлайн-мониторинг** — сквозная система отслеживания статуса серверов и сбора статистики онлайна в реальном времени. позволяет анализировать активность игроков и динамику развития различных проектов.

# Теперь об Backend стороне

## Список всех микросервисов:
Проект построен на базе микросервисной архитектуры. Ниже представлен список всех сервисов и их краткое назначение:

* **`GatewayApplication` (API Gateway)** — единая точка входа для всех внешних запросов (от фронтенда). отвечает за маршрутизацию трафика к соответствующим микросервисам и сквозную валидацию токенов.
* **`EurekaApplication` (Service Discovery)** — сервер базы данных и регистрации всех микросервисов. позволяет сервисам динамически находить друг друга в сети без жесткой привязки к ip-адресам.
* **`AuthServiceApplication` (Authentication Service)** — сервис авторизации. управляет сессиями, выдачей и обновлением токенов доступа, а также первичной аутентификацией пользователей через keycloak.
* **`AccountServiceApplication` (User Management)** — сервис управления профилями. отвечает за личные данные пользователей, изменение настроек аккаунта, сброс паролей и удаление учетных записей.
* **`ChatServiceApplication` (Chat Service)** — основной бизнес-сервис обмена сообщениями. управляет созданием диалогов и групп, историей переписки, статусами прочтения (через redis) и real-time соединением.
* **`EmailNotificationApplication` (Notification Service)** — сервис уведомлений. отправляет email-письма пользователям.
* **`DiscoveryServiceApplication` (Scraper & Reconnaissance Service)** — сервис сбора данных и веб-парсинга. отвечает за обход блокировок (анти-бот систем), извлечение полной html-разметки страниц, мониторинг онлайн-статусов внешних ресурсов и парсинг необходимых данных для нужд системы.
* **`Core` (Shared Library / Common Module)** — это не отдельный микросервис, а общая зависимость (библиотека) в виде jar-модуля. она подключается к остальным микросервисам проекта и содержит сквозные общие компоненты: глобальные DTO, перечисления (enum), кастомные бизнес-исключения (exception) и утилитарные классы для предотвращения дублирования кода.
* **`docker-compose` (Infrastructure Configuration Folder)** — это не сервис, а корневая папка проекта, содержащая конфигурацию инфраструктуры разработки. в ней находятся логи контейнеров (volumes), файлы конфигураций сторонних сервисов (например, центрифуги) и главный конфигурационный файл `docker-compose.yml`, который одной командой разворачивает все внешние зависимости, базы данных и брокеры сообщений.
* **`ems-frontend` (Frontend Application)** — папка, в которой находится вся клиентская часть приложения (фронтенд).





## 🔐 Auth Service (Authentication API)

сервис отвечает за аутентификацию пользователей, регистрацию новых аккаунтов, управление сессиями и обновление jwt-токенов с использованием oauth2/keycloak. авторизационные токены автоматически сохраняются в безопасных куках на стороне клиента.

**базовый url:** `/auth`

---

### 🚀 Эндпоинты API

#### 1. Аутентификация пользователя (Login)
выполняет проверку учетных данных пользователя. при успешной авторизации генерирует jwt-токены и устанавливает их в безопасные куки (`access_token`, `refresh_token`).

* **метод:** `POST`
* **путь:** `/login`
* **тело запроса (`LoginUserRequest`):**
  ```json
  {
    "username": "ivan_ivanov",
    "password": "my_secure_password_123"
  }
  ```

#### 2. Регистрация нового пользователя (Register)
создает новую учетную запись в системе. после успешного создания аккаунта автоматически производит вход пользователя (login), генерируя и устанавливая токены в куки.

* **метод:** `POST`
* **путь:** `/register`
* **тело запроса (`RegisterUserRequest`):**
  ```json
  {
    "username": "ivan_ivanov",
    "password": "my_secure_password_123",
    "email": "ivan@example.com"
  }
  ```

#### 3. Обновление токена доступа (Refresh)
использует долгоживущий `refresh_token` из кук для выпуска новой пары токенов (`access_token` и `refresh_token`), продлевая текущую сессию пользователя без необходимости повторного ввода логина и пароля.

* **метод:** `POST`
* **путь:** `/refresh`
* **заголовки / куки:**
  * `Cookie: refresh_token=<jwt_refresh_token>` (обязательный)
* **эффект:** обновляет значения и время жизни кук `access_token` и `refresh_token`.
* **тип ответа:** `JSON`
* **успешный ответ (`200 OK`):**
  ```json
  {
    "status": "success",
    "message": "Refresh token successfully",
    "timestamp": "2026-06-04T15:20:40Z"
  }
  ```





## 👤 AccountService (user management api)
Сервис отвечает за управление профилем пользователя, обновление личных данных, сброс паролей и завершение активных сессий (logout). 

**Базовый URL:** `/account`

---

### 🚀 Эндпоинты API

#### 1. Получение информации о пользователе
Возвращает профиль текущего авторизованного пользователя на основе валидного JWT-токена доступа.

* **Метод:** `GET`
* **Путь:** `/userInfo`
* **Заголовки / Куки:**
  * `Cookie: access_token=<jwt_token>` (Обязательный)
* **Тип ответа:** `UserProfileDto`
* **Успешный ответ (`200 OK`):**
  ```json
  {
    "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "username": "ivan_ivanov",
    "name": "Иван Иванов",
    "firstName": "Иван",
    "lastName": "Иванов",
    "email": "ivan@example.com",
    "emailVerified": true
  }
  ```
  
#### 2. Обновление данных профиля
изменяет персональные данные пользователя. идентификация происходит по внутреннему заголовку шлюза.

* **метод:** `PUT`
* **путь:** `/update`
* **заголовки:**
  * `X-User-Id: <UUID>` (подставляется автоматически api gateway)
* **тело запроса (`UpdateDataUserRequest`):**
  ```json
  {
    "username": "new_username",
    "password": "optional_new_password",
    "firstName": "Иван",
    "lastName": "Новый-Иванов",
    "email": "new_email@example.com"
  }
  ```
#### 3. сброс пароля
позволяет авторизованному пользователю установить новый пароль для своей учетной записи.

* **метод:** `PUT`
* **путь:** `/reset`
* **заголовки:**
  * `X-User-Id: <UUID>` (подставляется автоматически api gateway)
* **тело запроса (`ResetPasswordRequest`):**
  ```json
  {
    "newPassword": "my_secure_new_password_123"
  }
  ```
#### 4. выход из системы (logout)
инвалидирует сессию пользователя на стороне oauth2/keycloak и полностью очищает авторизационные куки на клиенте.

* **метод:** `POST`
* **путь:** `/logout`
* **заголовки / куки:**
  * `Cookie: refresh_token=<jwt_refresh_token>` (обязательный)
* **эффект:** полностью удаляет куки `access_token` и `refresh_token` на стороне клиента (устанавливает `maxAge = 0`, `path = "/"` и флаг `HttpOnly`).
* **тип ответа:** `JSON`
* **успешный ответ (`200 OK`):**
  ```json
  {
    "status": "success",
    "message": "Logout user successfully",
    "timestamp": "2026-06-04T15:10:37Z"
  }
  ```

#### 5. удаление аккаунта
полностью удаляет учетную запись пользователя из системы и очищает сессионные куки на клиенте.

* **метод:** `POST`
* **путь:** `/delete/{id}`
* **параметры пути:**
  * `id` — уникальный идентификатор удаляемого пользователя (UUID / String).
* **эффект:** полностью удаляет куки `access_token` и `refresh_token` на стороне клиента (устанавливает `maxAge = 0`, `path = "/"` и флаг `HttpOnly`).
* **тип ответа:** `JSON`
* **успешный ответ (`200 OK`):**
  ```json
  {
    "status": "success",
    "message": "Delete user successfully",
    "timestamp": "2026-06-04T15:11:00Z"
  }
  ```





## 📧 Email Notification Service (Email API)

сервис отвечает за отправку писем на электронную почту (через gmail), подтверждение email-адресов пользователей и верификацию операций удаления аккаунтов с помощью временных токенов и кодов подтверждения.

**базовый url:** `/email`

---

### 🚀 Эндпоинты API

#### 1. Подтверждение email-адреса (Confirm Email)
обрабатывает переход по ссылке из письма для верификации почты. проверяет валидность токена и его срок действия, после чего выполняет редирект пользователя в личный кабинет на фронтенд.

* **метод:** `GET`
* **путь:** `/confirm`
* **параметры запроса (query params):**
  * `token` — уникальный строковый токен верификации из ссылки.
* **эффект:** активирует статус подтвержденной почты и возвращает статус `302 Found` для перенаправления браузера.
* **тип ответа:** `Редирект (Headers)`
* **успешный ответ (`302 Found`):**
  * **заголовки:** `Location: http://localhost:3000/lk?verified=true`

#### 2. Подтверждение удаления аккаунта (Confirm Delete Account)
верифицирует код подтверждения для удаления учетной записи пользователя.

* **метод:** `GET`
* **путь:** `/delete/confirm`
* **заголовки:**
  * `X-User-Id: <UUID>` (подставляется автоматически api gateway)
* **параметры запроса (query params):**
  * `code` — секретный код подтверждения, отправленный на почту.
* **тип ответа:** `JSON`
* **успешный ответ (`200 OK`):**
  ```json
  {
    "status": "success",
    "message": "Delete account success",
    "timestamp": "2026-06-04T15:31:01Z"
  }
  ```

#### 3. Отправка письма для подтверждения почты (Send for Verify)
генерирует токен верификации и отправляет на указанный email-адрес письмо со ссылкой для подтверждения.

* **метод:** `POST`
* **путь:** `/send-for-verify`
* **заголовки:**
  * `X-User-Id: <UUID>` (подставляется автоматически api gateway)
* **параметры запроса (query params):**
  * `email` — адрес электронной почты, на который нужно отправить письмо.
* **тип ответа:** `JSON`
* **успешный ответ (`200 OK`):**
  ```json
  {
    "status": "success",
    "message": "Send message successfully on a gmail address",
    "timestamp": "2026-06-04T15:33:40Z"
  }
  ```

#### 4. Отправка письма для удаления аккаунта (Send for Delete Account)
генерирует одноразовый код и отправляет его на почту пользователя для подтверждения намерения удалить профиль.

* **метод:** `POST`
* **путь:** `/send-for-delete-account`
* **заголовки:**
  * `X-User-Id: <UUID>` (подставляется автоматически api gateway)
* **параметры запроса (query params):**
  * `email` — адрес электронной почты пользователя.
* **тип ответа:** `JSON`
* **успешный ответ (`200 OK`):**
  ```json
  {
    "status": "success",
    "message": "Send message successfully on a gmail address",
    "timestamp": "2026-06-04T15:34:10Z"
  }
  ```

## 💬 Chat Service (Centrifugo Integration API)

раздел описывает контроллер, отвечающий за интеграцию с real-time сервером centrifugo. он обрабатывает вебхуки авторизации подключений от самого centrifugo и координирует сетевой статус пользователей (online/offline) через брокер сообщений.

### 📋 Класс: `CentrifugoConnectController`
**базовый url:** `/api/centrifugo`

---

### 🚀 Эндпоинты API

#### 1. Авторизация подключения к веб-сокетам (Connect Webhook)
вызывается сервером centrifugo при попытке клиента установить веб-сокет соединение. проверяет пользователя, формирует результат авторизации и публикует в глобальный канал событие о том, что юзер зашел в сеть.

* **метод:** `POST`
* **путь:** `/connect`
* **полный путь:** `/api/centrifugo/connect`
* **заголовки:**
  * `X-User-Id: <UUID>` (идентификатор пользователя, прошедший через api gateway)
* **тип ответа:** `JSON`
* **успешный ответ (`200 OK`):**
```json
  {
    "result": {
      "user": "123e4567-e89b-12d3-a456-426614174000"
    }
  }
```

#### 2. Обработка отключения от веб-сокетов (Disconnect Webhook)
вызывается сервером centrifugo, когда клиент разрывает соединение с веб-сокетами. фиксирует выход пользователя из сети и уведомляет об этом систему.

* **метод:** `POST`
* **путь:** `/disconnect`
* **полный путь:** `/api/centrifugo/disconnect`
* **тело запроса (body):**
```json
  {
    "user": "123e4567-e89b-12d3-a456-426614174000"
  }
```

#### 7. Удаление чата (Delete Chat)
полностью удаляет чат со всеми сообщениями. для групповых чатов операция доступна исключительно владельцу (создателю) группы.

* **метод:** `DELETE`
* **путь:** `/{chatId}`
* **полный путь:** `/chats/456e4567-e89b-12d3-a456-426614174111`
* **заголовки:**
  * `X-User-Id: <UUID>`
* **тип ответа:** `отсутствует (Void)`
* **успешный ответ (`204 No Content`):** `Пустое тело ответа`

#### 8. Выход из группового чата (Leave Chat)
позволяет обычному пользователю самостоятельно покинуть групповой чат, исключив себя из списка участников.

* **метод:** `POST`
* **путь:** `/{chatId}/leave`
* **полный путь:** `/chats/456e4567-e89b-12d3-a456-426614174111/leave`
* **заголовки:**
  * `X-User-Id: <UUID>`
* **тип ответа:** `отсутствует (Void)`
* **успешный ответ (`200 OK`):** `Пустое тело ответа`

#### 9. Включение/выключение уведомлений (Toggle Mute)
изменяет режим уведомлений для конкретного чата (включает или отключает звук и индикацию обновлений на левой панели).

* **метод:** `PATCH`
* **путь:** `/{chatId}/mute`
* **полный путь:** `/chats/456e4567-e89b-12d3-a456-426614174111/mute`
* **параметры запроса (query params):**
  * `userId` — идентификатор пользователя.
* **тип ответа:** `JSON`
* **успешный ответ (`200 OK`):**
```json
  {
    "isMuted": true
  }
```
